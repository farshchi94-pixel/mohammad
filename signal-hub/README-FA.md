# آموزش راه‌اندازی «رادار سیگنال» (فقط با گوشی، رایگان)

## این پروژه چه می‌کند؟
- هر ۱۵ دقیقه ۳۰ ارز را اسکن می‌کند: اول جهت ۴ساعته، بعد تأیید ۱۵دقیقه. فقط وقتی هر دو کامل شد سیگنال می‌دهد.
- هر سیگنال را با زمان ثبت می‌کند و خودکار با هدف یا حد ضرر می‌بندد. رکورد واقعی (درصد برد، میانگین R، بیشترین افت) از همین‌جا ساخته می‌شود.
- پوزیشن‌های کیف پول‌های برتر Hyperliquid و (اختیاری) خرید و فروش کیف پول‌های سولانا را دنبال می‌کند.
- نتیجه را به تلگرام می‌فرستد و در یک سایت فارسی نشان می‌دهد.

## کلیدهایی که لازم دارید (همه اختیاری‌اند، بدون آن‌ها هم سایت کار می‌کند)
| نام | برای چه | کجا بگیرم |
|---|---|---|
| TELEGRAM_TOKEN | ارسال پیام به تلگرام | تلگرام ← @BotFather ← /newbot |
| TELEGRAM_CHAT_ID | مقصد پیام | آیدی کانال مثل @mychannel (ربات را ادمین کانال کنید) |
| HELIUS_API_KEY | کیف پول‌های سولانا | helius.dev ← ثبت‌نام رایگان ← API Key |
قیمت‌ها و Hyperliquid کلید نمی‌خواهند.

## مرحلهٔ ۱: ساخت حساب و مخزن
1. در مرورگر به github.com بروید و حساب بسازید.
2. بالا سمت راست + ← New repository. اسم: `radar`. گزینهٔ **Public** را بزنید. Create repository.

## مرحلهٔ ۲: آپلود فایل‌ها
1. فایل زیپ را در گوشی باز کنید (روی آن بزنید تا از حالت فشرده خارج شود).
2. در صفحهٔ مخزن: Add file ← Upload files. این فایل‌ها را انتخاب کنید: `index.html`، `scan.py`، `whale_pro.py`، `market.py`، `optimize.py`، `card.py`، `watch.py`، `consensus.py`، `trader.py`، `wave_rider.py`، `config.json`. پایین صفحه Commit changes.

## مرحلهٔ ۳: ساخت فایل workflow (مهم)
1. Add file ← **Create new file**.
2. در کادر اسم دقیقاً بنویسید: `.github/workflows/scan.yml` (با نقطهٔ اول و اسلش‌ها؛ خودش پوشه می‌سازد).
3. محتوای فایل `workflow-scan.yml` را کپی و داخل کادر paste کنید. Commit changes.

## مرحلهٔ ۴: گذاشتن کلیدها
1. مخزن ← Settings ← Secrets and variables ← Actions ← New repository secret.
2. برای هر کلیدی که دارید، یک secret با همان اسم جدول بالا بسازید (Name و Secret). کلید را هرگز داخل فایل‌ها ننویسید.

## مرحلهٔ ۵: روشن کردن سایت
1. Settings ← Pages ← Source: Deploy from a branch ← Branch: `main` و پوشه `/ (root)` ← Save.
2. بعد از یکی دو دقیقه آدرس بالای همان صفحه ظاهر می‌شود: `https://نام‌کاربری.github.io/radar/`

## مرحلهٔ ۶: اولین اجرا
1. تب **Actions** ← از لیست `scan` ← Run workflow ← Run workflow.
2. حدود یک دقیقه صبر کنید تا سبز شود. اگر قرمز شد، روی آن بزنید، بخش «Run scanner» را باز کنید و **متن آخرین خطوط** را برای من بفرستید.
3. اگر سبز شد، سایت را باز کنید. از این به بعد هر ۱۵ دقیقه خودش به‌روز می‌شود (GitHub گاهی تا چند دقیقه دیرتر اجرا می‌کند).

## «بازار» چطور وصل می‌شود؟ (واقعیت)
هیچ لایهٔ جداگانه‌ای برای وصل کردن نیست. همین کد با اینترنت اجرا می‌شود و قیمت‌ها را از API های **عمومی** (MEXC، Gate، Hyperliquid، DexScreener و ...) می‌خواند و کلید نمی‌خواهد. من نمی‌توانم آن را برایتان اجرا کنم، چون محیط من به این سایت‌ها دسترسی ندارد و برنامه‌ای را شبانه‌روز اجرا نگه نمی‌دارد. خودتان یک بار طبق مراحل بالا GitHub Actions را روشن کنید (حدود ۱۰ تا ۱۵ دقیقه). بعد از آن خودش هر ۱۵ دقیقه واقعی کار می‌کند. اگر پیامی از خطا دید، متنش را برایم بفرستید.

## ترید خودکار: سه مرحله
1. **حساب کاغذی خودکار (فعال است):** تب «حساب کاغذی». با سیگنال‌های ویل پرو و اجماع، سایز را از روی ریسک ٪ حساب می‌کند، با قیمت واقعی و کارمزد و لغزش پوزیشن باز و بسته می‌کند. تنظیمات در `config.json` بخش `trading` (`risk_pct`, `max_open`, `max_leverage`, `daily_loss_pct`, `kill_switch`, `sources`).
2. **ارسال به ربات وب‌هوک خودتان:** اگر قبلاً ربات وب‌هوک (مثلاً با TradingView) دارید، `mode` را `"both"` یا `"webhook"` کنید و `webhook_url` را بگذارید. هر سیگنال تازه یک بار با این بدنه POST می‌شود (قالب قابل‌تغییر با `webhook_body`): `{"id":..., "action":"buy|sell", "symbol":..., "sl":..., "tp1":..., "tp2":..., "risk_pct":...}`. اجرای سفارش با ربات خودتان است، نه با این پروژه.
3. **سفارش مستقیم به صرافی:** عمداً هنوز ساخته نشده. اول باید حساب کاغذی چند ماه و ده‌ها معامله سودده بماند. بعد با کلید «فقط معامله» (بدون برداشت)، روی testnet و مبلغ ناچیز، با حد ضرر روی خود صرافی. هر سرویس رایگان با آی‌پی متغیر (مثل GitHub) برای کلید معاملاتی مناسب نیست؛ آن موقع سرور (VPS) با آی‌پی ثابت لازم است.

## موج‌سوار (موج‌های ۵ تا ۱۵ دقیقه‌ای): جدا از GitHub، باید همیشه روشن باشد
اسکالپ دقیقه‌ای با GitHub Actions شدنی نیست (حداقل فاصلهٔ اجرا ۵ دقیقه است و دیر هم اجرا می‌شود). `wave_rider.py` یک برنامهٔ همیشه‌روشن است که هر ۱۰ ثانیه کندل‌های ۱دقیقه‌ای را می‌خواند.

**کجا اجرا کنم؟** یک سرور مجازی ارزان (VPS)، کامپیوتر یا Raspberry Pi که همیشه روشن باشد و به اینترنت وصل باشد. (Oracle Cloud Always Free هم گزینهٔ رایگان است.)

**اجرا:**
```
pip install requests
export TELEGRAM_TOKEN=...  TELEGRAM_CHAT_ID=@yourchannel   # اختیاری
export WAVE_TOKEN=یک-رمز-دلخواه-طولانی                    # برای ویرایش تنظیمات از وب
python wave_rider.py --serve 8080
```
بعد در مرورگر: `http://آدرس-سرور:8080/` را باز کنید، تب «موج‌سوار» (همان `index.html`). برای اجرای دائمی: `nohup python wave_rider.py --serve 8080 &` یا systemd/pm2. فقط پورت 8080 را برای خودتان باز کنید (فایروال یا VPN)؛ همهٔ تغییر تنظیمات با `WAVE_TOKEN` محافظت شده ولی صفحه خودش عمومی است.

**چطور کار می‌کند:**
- **ستاپ «فشردگی و کف نگه‌داشته»:** ارز چند دقیقه در یک دامنهٔ تنگ می‌ماند، کفش را حداقل ۲ بار نگه می‌دارد (وضعیت «آماده»)، بعد بالای دامنه با جهش حجم و کندل قوی می‌بندد ← ورود. برای شورت برعکس.
- **ستاپ «شکست سطح»:** شکست سقف یا کف ۶۰ دقیقه‌ای با حجم.
- **ورود ضد تعقیب:** اگر قیمت از سطح شکست زیادی دور شده باشد وارد نمی‌شود.
- **خروج:** TP1 در نیمهٔ راه هدف و بستن ۵۰٪، بعد حد ضرر به نقطهٔ ورود (ریسک‌فری، با پوشش کارمزد)، و بقیه در هدف نهایی یا با حد ضرر متحرک (حالت «سواری»). معاملهٔ مرده بعد از `max_minutes` بسته می‌شود.
- **حالت خودکار نوسان (`adaptive`):** حد ضرر و هدف از روی ATR دقیقه‌ای ساخته می‌شود؛ روزهای پرنوسان بزرگ‌تر و روزهای آرام کوچک‌تر. خاموشش کنید تا حد ضرر و هدف ثابت (٪) به کار بروند.
- **همه‌چیز قابل‌تنظیم** از تب «موج‌سوار» (پایین صفحه) یا `config.json` بخش `wave`. مقدارهای خارج از محدودهٔ مجاز خودکار اصلاح می‌شوند.
- **فقط کاغذی است.** کارمزد و لغزش لحاظ می‌شود و «کلید توقف اضطراری» دارد.

**اهرم ۲۵ تا ۳۰؛ واقعیت‌ها:**
- اندازهٔ پوزیشن از **ریسک ٪** و فاصلهٔ حد ضرر می‌آید، نه از اهرم. اهرم فقط مارجین را تعیین می‌کند. با ریسک ۰٫۵٪ و حد ضرر ۰٫۳٪، ضرر یک معامله حدود ۰٫۵٪ سرمایه است، چه اهرم ۱۰ باشد چه ۳۰.
- برنامه اگر حد ضرر نسبت به فاصلهٔ لیکویید بیش از حد دور باشد وارد نمی‌شود (`liq_buffer`).
- هزینهٔ رفت‌وبرگشت (کارمزد و لغزش) با اهرم ۲۵ حدود ۳٫۵٪ مارجین است. با حد ضرر تنگ ۰٫۳٪ این هزینه حدود ۰٫۴ تا ۰٫۵R از هر معامله می‌خورد. تب نشان می‌دهد در معاملات واقعی چقدر کارمزد داده شده. اگر میانگین کارمزد به R بالا بود، این روش در عمل سود نمی‌دهد.
- هدف‌های کوچک (۰٫۴٪) را برنامه رد می‌کند چون کارمزد آن‌ها را می‌خورد (`min_target_cost_mult`).

**پیش از هر پول واقعی:** حساب کاغذی را روی بازار زنده حداقل ۲ تا ۴ هفته و ده‌ها معامله بسنجید. اگر خالصِ بعد از کارمزد مثبت نبود، پارامترها یا روش را عوض کنید، نه اهرم را.

## مرکز فرماندهی: اجماع «۴ از ۶» (الهام‌گرفته از ویدیوهای ATSMATRIX، ولی با اعداد واقعی)
ایدهٔ اصلی: یک سیگنال فقط وقتی صادر می‌شود که چند عامل مستقل با هم موافق باشند. شش عامل برای ارزهای صرافی:
1. **TECH**: تکنیکال. سیگنال یا پوزیشن هم‌جهت ویل پرو، یا تأیید کامل ۱۵دقیقه. این عامل **اجباری** است (زمان‌بندی ورود).
2. **TREND**: جهت ۴ساعته با امتیاز حداقل ۳.
3. **MARKET**: بیت‌کوین مخالف نباشد و ترس و طمع در حد افراطی مخالف نباشد.
4. **SMART$**: جریان کیف پول‌های برتر Hyperliquid در همان جهت (حداقل ۲ کیف پول و ۲۵٪ عدم‌توازن).
5. **DERIV**: فاندینگ و نسبت لانگ/شورت (Gate Futures). معامله علیه ازدحام. فقط وقتی دو رأی اول موافق باشند بررسی می‌شود.
6. **RISK**: بلک‌اوت خبر فعال نباشد (این یک وتو هم هست) و آنلاک توکن در ۳ روز آینده نباشد.
- حداقل رأی و عامل‌های اجباری در `config.json` (`consensus_min`، `consensus_required`).
- **تقویم آنلاک:** در `unlocks` بنویسید، مثل `[{"sym": "SUI", "date": "2026-11-01"}]` (تاریخ‌ها را از سایت‌هایی مثل tokenomist یا CoinMarketCap خودتان بردارید).
- **شاخهٔ DEX/سولانا:** از خرید کیف پول‌های `solana_wallets` (با کلید Helius) توکن‌ها را می‌سازد و ۶ رأی می‌دهد: نهنگ، چند کیف پول، RugCheck بدون خطر، نقدشوندگی، مومنتوم زودهنگام، تمرکز دارندگان. هر مورد خطرناک RugCheck وتو است. نتیجه فقط پایش کاغذی است (سود/افت بعد از ثبت).
- **قیف و دفتر کاغذی:** تعداد بررسی‌شده، ≥۳ رأی و صادرشده شمرده می‌شود. هر سیگنال اجماع با زمان ثبت و با هدف یا حد ضرر بسته می‌شود. این اعداد واقعی‌اند، نه انیمیشن.
- **هشدار صادقانه:** اجماع بالا یعنی چند نشانه هم‌جهت‌اند، نه سود تضمینی. تا چند ماه و ده‌ها معاملهٔ بسته‌شده در دفتر کاغذی، با پول واقعی کار نکنید.

## فایل دوم workflow (بهینه‌سازی هفتگی)
مثل مرحلهٔ ۳ یک فایل دیگر بسازید: Add file ← Create new file با اسم `.github/workflows/optimize.yml` و محتوای `workflow-optimize.yml`. هفته‌ای یک بار (یکشنبه) و هر وقت دستی بزنید، گزارش پایداری استراتژی را می‌سازد.

## بخش‌های حرفه‌ای جدید
- **کارت حرفه‌ای تلگرام:** هر سیگنال ویل پرو با یک تصویر (چارت کندلی، ورود، حد ضرر، TP1 و TP2 با R) به تلگرام می‌رود. روی کارت «حداقل نرخ برد لازم برای سربه‌سر شدن» هم نوشته می‌شود. نتیجهٔ هر معامله با یک کارت جدا (برد یا باخت) و هر یکشنبه «رکورد زنده» با همهٔ معاملات، حتی باخت‌ها، ارسال می‌شود. متن کارت‌ها انگلیسی است (به‌خاطر محدودیت رندر فارسی)، توضیح تلگرام فارسی است.
- **تب «بازار و اخبار»:** ساعت بازشدن توکیو، لندن، نیویورک و بازار سهام آمریکا به وقت تهران، تقویم اقتصادی (CPI، FOMC، NFP...) با شمارش معکوس، تیتر اخبار، شاخص فصل آلت‌کوین (محاسبهٔ خودمان) و نبض Hyperliquid.
- **فیلتر اخبار:** ±۳۰ دقیقه حول رویدادهای High دلاری، ربات سیگنال جدید نمی‌دهد (`news_blackout_min` در `config.json`). این فیلتر فقط برای لحظهٔ حال است؛ بک‌تست گذشته رویدادهای قدیمی را نمی‌داند.
- **ارتقاهای اختیاری استراتژی** (همه به‌صورت پیش‌فرض خاموش؛ تنظیمات Pine شما دست‌نخورده است). در `whale_params` روشن کنید:
  - `"stop_mode": "atr"` همراه `atr_mult_stop`, `atr_mult_tp1`, `atr_mult_tp2`: حد ضرر و تارگت بر پایهٔ نوسان.
  - `"htf_filter": true` (فیلتر روند ۴ساعته، `whale_htf` تایم‌فریم بالاتر): فقط هم‌جهت با روند بزرگ‌تر.
  - `"daily_loss_pct": 1.5`: بعد از ضرر روزانهٔ ۱٫۵٪ سرمایه، ورود جدید متوقف شود.
- **تب «بهینه‌سازی»:** تنظیمات شما را روی ۶۰٪ اول داده (آموزش) و ۴۰٪ آخر دیده‌نشده (آزمون) می‌سنجد، همسایه‌های پارامترها را بررسی می‌کند و با مونت‌کارلو بدترین افت محتمل را تخمین می‌زند. اگر در آزمون سودده نبود، یعنی احتمال بیش‌برازش است. دقت کنید: یافتن «بهترین پارامتر گذشته» تضمین سود آینده نیست.
- **تب «رقبا»:** در `config.json` نام کانال‌های تلگرامی عمومی را در `watch_channels` بنویسید (مثلاً `["channelname"]`). ربات پست‌های عمومی را می‌خواند، سیگنال‌های دارای ورود، هدف و حد ضرر را استخراج می‌کند و با کندل‌های واقعی می‌سنجد چه شد: برد واقعی، سیگنال دیرهنگام، لیکویید شدن و افت بیشینه. فقط برای تحلیل و یادگیری است؛ محتوای آن‌ها را بازنشر نکنید.

## تب «ویل پرو» (استراتژی Pine خودتان)
- فایل `whale_pro.py` همان کد Pine شماست (Whale Pro V3.10) که به پایتون برگردانده شده: همان اندیکاتورها (EMA/RSI/ADX/MACD که با TA-Lib راستی‌آزمایی شدند)، مدل Hybrid، فیلتر ADX و حجم، روند Soft، تأیید با کندل بعد، کول‌داون، انتقال به سربه‌سر بعد از TP1، تایم‌اوت و الگوی M/W.
- اجرای معاملات مثل TradingView است: سفارش در پایان کندل ثبت و در بازشدن کندل بعد پر می‌شود؛ SL و TP درون کندل با مسیر O-H-L-C بررسی می‌شوند؛ SL و TPها از قیمت بستهٔ کندل سیگنال محاسبه می‌شوند.
- چارت: کندل‌های واقعی، EMA8/21/55/200، علامت BUY/SELL، هدف‌ها و حد ضرر، قیمت روی محور، و لمس هر کندل برای دیدن OHLC.
- رکورد زنده فقط معاملاتی را می‌شمارد که بعد از روشن شدن ربات شروع شده‌اند. بک‌تست مربوط به گذشته است.
- تنظیمات در `config.json`:
  - `whale_symbols`: ارزهایی که اجرا شود. `whale_tf`: تایم‌فریم (مثلاً 15m یا 5m).
  - `whale_params`: هر ورودی Pine را اینجا عوض کنید، با همان اسم‌ها. مثال: `{"stop_pct": 0.8, "tp1_pct": 0.4, "model": "Breakout", "use_mw_pattern": true, "min_adx_val": 20}`
- تفاوت‌های احتمالی با TradingView: منبع قیمت (MEXC/Gate در برابر صرافی چارت شما) و شمع‌های لحظه‌ای. بنابراین اعداد ممکن است کمی فرق کنند، ولی منطق یکی است.
- برای سنجیدن، حتماً بک‌تست و رکورد زنده را ببینید. اگر سودآور نبود، قبل از معامله واقعی پارامترها را روی چند ارز و بازه‌های مختلف بسنجید.

## چطور بخوانمش؟
- **سیگنال زنده:** فقط ارزهای اصلی با تأیید قوی. **تمرینی:** میم‌کوین و سیگنال‌های ضعیف‌تر، فقط برای آزمایش.
- **رکورد:** تا حدود ۳۰ معامله بسته‌شده، آمار قابل‌اتکا نیست. ۳۰ تا ۶۰ روز فقط تماشا کنید و بدون پول واقعی بسنجید.
- **نهنگ‌ها:** پوزیشن‌های عمومی. کپی‌کردن بی‌فکر خطرناک است.
- **نمادها:** وضعیت هر ارز و شرط‌های ۱۵دقیقه.

## تغییر لیست ارزها یا کیف پول‌ها
فایل `config.json` را در GitHub باز کنید ← آیکون مداد ← تغییر دهید ← Commit.
- `majors` و `memes`: نمادها با پسوند USDT.
- `hyperliquid_wallets`: آدرس‌های اضافه (۰x…) برای دنبال کردن.
- `solana_wallets`: آدرس کیف پول‌های سولانا (برای این کار HELIUS_API_KEY لازم است).

## نکات مهم
- «آنلاین» اینجا یعنی هر ۱۵ دقیقه، نه لحظه‌ای. برای لحظه‌ای باید روی سرور (VPS) اجرا شود.
- منبع قیمت MEXC و Gate است (از سرورهای آمریکا باز می‌شوند). قیمت صرافی خودتان ممکن است کمی فرق کند.
- در سایت و ربات هیچ تضمینی برای سود نیست. حداکثر ۱٪ سرمایه ریسک کنید و اهرم بالا نگیرید.
- اگر روزی سایت نوشت «داده قدیمی است»، تب Actions را بررسی کنید.
